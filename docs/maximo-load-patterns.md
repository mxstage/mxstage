# Maximo の標準の読み込み・投入のパターンと、MX Stage でできること

2026-10-03 の調べ（IBM の公式の文書を中心に、コミュニティの記事も使った）。標準オブジェクトの Skill を選ぶための材料。

**2026-10-08 追記:** その後、親のレコードの新規作成（0.2.6）と状態の変更（0.2.7。作成・更新を確かめた後に `wsmethod:changeStatus` で変え、読み直す）に対応した。状態の移り方の決まりを製品が知っているのは作業指示・発注・サービス要求だけで、資産などはそのまま Maximo の決まりに任せる（試していない）。下の表の △ のうち、この 2 つに当たるものは今は動く。
出典の URL は 7 章にまとめた。**（未確認）** は一次資料で確かめられなかったもの。頻度（よく行う／ときどき／まれ）は実務の記事からの判断で、IBM が示したものではない。

「MX Stage」の列の意味:

- **○** 今できる（既存のレコードの属性の書き換え、または同じ構造の中の子の行の追加・変更・削除）
- **△** 条件付き（構造にその属性が含まれているか、本物の Maximo で確かめる必要がある）
- **×** 今はできない（専用の処理・改訂・在庫の取引）。新規作成は 0.2.6 からできる（番号を入れて作る。自動採番は使わない）

## 1. どのオブジェクトにも共通の決まり

| 決まり | 内容 | MX Stage |
|---|---|---|
| 子の行は MERGE で送る | MERGE なしの PATCH は、送らなかった子の行を消す。子の削除は `_action: "Delete"` | 済み（反映は必ず MERGE。外せない作り） |
| 二重送信を防ぐ | 書き込みごとに一意の `transactionid` を付ける。同じものは 409 で断られる | 済み（409 は読み直して確かめる） |
| 状態は普通の項目ではない | 最上位のレコードの STATUS を PATCH すると、Maximo は本物の状態の変更（履歴を含む）として処理する。IBM の開発者は wsmethod より PATCH を勧めている。**子の行（作業のタスクなど）の状態は対象外**。状態の移り方の決まりは守られる（作業指示は完了→クローズのみ、取消・クローズは最後など） | △ 作業指示・発注・購買依頼は PATCH で動く見込み。資産・予防保全は専用の処理（wsmethod）が要る見込み |
| 非永続の項目で専用の処理が動く | 資産の移動（NEWLOCATION・NEWSITE）、メーターの読み値（NEWREADING）、実地棚卸（ADJUSTEDPHYSCNT）など。構造に含まれていないと無視される。MAS 9 の MXAPI の構造は編集できない | △ 構造の属性を確かめてから |
| 権限 | MAS 9 は構造ごとにセキュリティグループの許可が要る（既定で有効） | 利用者の環境の設定 |
| 読み込みの順 | 親から子へ（分類 → 場所 → 親の資産 → 子の資産） | 新規作成は 0.2.6 から。参照されるものを先の反映で作る |
| Excel の崩れ | 日付の数値化、先頭の 0 の欠落、指数表記 | 取り込みで確かめる |
| 関連の項目を読む | `oslc.select` で関連の MBO の項目を読める（例 `classstructure.hierarchypath`）。読むだけ。1 行ごとに SQL が増える | × 今は列名の「.」を子の項目と見なすので読めない |

## 2. オブジェクト × 操作

### 資産（MXAPIASSET）

| 操作 | 頻度 | Maximo の手段・決まり | MX Stage |
|---|---|---|---|
| 資産台帳の一括の修正（説明・メーカー・製造番号・優先度など） | よく行う | 属性の書き換え | ○ |
| 仕様の値の補完・修正（ASSETSPEC） | よく行う | 子の行の書き換え。回転品目の資産は品目の仕様を引き継ぐ（ITEMSPECVALCHANGED） | ○ |
| 分類の付け替え | よく行う | **既存の仕様の行を消して、分類の定義から空の行を作り直す**。同じ分類を送り直しても消えた例がある | ○ ただし必ず事前に警告 |
| 状態の変更（稼働・廃止） | ときどき | 専用の処理。廃止は子の資産へ伝わり、有効な予防保全・ルートなどがあると止まる。メモは送れない | △ 0.2.7 は `wsmethod:changeStatus` を送るが、資産では試していない |
| 場所の移動 | よく行う | LOCATION の書き換えは移動ではない。NEWLOCATION・NEWSITE で移動の処理が動く。移動の履歴が残るかは経路による | △ 構造に NEWLOCATION があれば |
| 親（階層）の付け替え | ときどき | 移動として扱う。親の場所に引っ張られる。階層を保つ設定だと子だけは動かせない | △ 移動と同じ扱い、要確認 |
| メーターの付与（ASSETMETER） | ときどき | 子の行 | ○ |
| 予備品・故障の分類・回転品目 | ときどき | 属性・子の行 | ○ |
| 新しい資産の登録 | よく行う（移行） | 新規作成。資産番号は自動採番が多い | ○（番号を入れて作る。自動採番は使わない） |

| 仕様の値（LOCATIONSPEC） | よく行う | 資産の仕様と同じ | ○ |

| 階層の新規登録 | よく行う（移行） | 上から順に新規作成 | ○（番号を入れて作る。自動採番は使わない） |

## 3. MX Stage の課題（Skill に書かず、製品として足すもの）

| 課題 | 何ができるようになるか | 標準の手段 | 見込み |
|---|---|---|---|
| 最上位のレコードの新規作成 | 資産・場所・品目などの新規登録、移行 | 一覧への POST。キーで照合して無ければ作る送り方（SYNC＋MERGE）もある。自動採番は送らずに結果から読む | **0.2.6 で実装**（一覧への POST。送る前と後にキーで探す。自動採番は未対応） |
| 状態の変更 | 一括の承認・クローズ・廃止 | 作業指示・発注・購買依頼は STATUS の PATCH。資産・予防保全は専用の処理（changeStatus） | 標準の手段がある |
| 関連の項目を読む | 資産のシートに分類の階層パス（`classstructure.hierarchypath`）を直接入れる | `oslc.select` の関連の指定（読むだけ） | 標準の手段がある。列名の決め方を変える |
| 非永続の項目の扱い | 資産の移動・メーターの読み値・実地棚卸 | 構造に含まれる非永続の項目の PATCH | 構造による。要確認 |
| 改訂・資産の入れ替え・在庫の調整・受入・実績 | 有効な作業計画・承認済みの発注の変更など | 標準の REST の処理が確認できない（客先の自動化スクリプトで作る例が多い） | 対象外にする |

## 4. 標準オブジェクトの Skill の候補（厳選の案）

| Skill | 主な作業（今できるもの） | 書くべき注意 |
|---|---|---|
| `mxstage-obj-asset` | 台帳の一括の修正、仕様の補完、メーターの付与 | 分類の付け替えは仕様を消す。移動は NEWLOCATION（構造による）。回転品目の仕様 |
| `mxstage-obj-location` | 属性と仕様の修正 | 状態・親の付け替えの決まり |
| `mxstage-obj-classification` | 分類の定義と階層パスの確認、欠けの補完、単位と型の確認 | 分類の付け替えの影響、表の型の値 |
| `mxstage-obj-workorder` | 未完了の作業指示の修正、計画の資材・労務 | クローズ・取消は直せない、タスクの状態は変えない、状態の移り方 |
| `mxstage-obj-pm-jobplan` | 予防保全の日程の見直し、下書き・改訂中の作業計画の修正 | マスターの予防保全の上書き、有効な作業計画は改訂が要る |
| `mxstage-obj-item-inventory` | 品目の属性、在庫の発注点・棚・棚卸の頻度 | 数量の調整は取引でできない、単位の変更の制約 |
| `mxstage-obj-purchasing` | 承認待ちの購買依頼・発注の明細の修正 | 承認済みは改訂、受入は取引 |
| `mxstage-obj-reference` | 人員・労務・人員グループ・取引先・ドメインの整理 | ドメインの値の対応 |

状態の変更・新規作成ができるようになったら、それぞれの Skill に足す。

## 5. 確かめ方

- 仮想 Maximo にある構造: 組織・運用場所・資産・分類・資産属性・単位・故障コード・故障の一覧・作業計画・予防保全・作業指示・サービス要求・
  メーター・メーターの読み値・品目・在庫・人員・労務・職種・人員グループ・会社・ドメイン。
  **購買依頼・発注・受入は無い**ので、購買の Skill を選ぶなら足す。
- 仮想 Maximo は Maximo の業務ロジック（状態の移り方、分類の付け替えでの仕様の作り直し、移動の処理など）を持たない。
  これらは仮想 Maximo に決まりを足すか、本物の Maximo で確かめる。
- **本物の Maximo で確かめること**: 資産の状態の変更の送り方、MXAPIASSET に NEWLOCATION があるか、作業指示の STATUS の PATCH とメモの項目名、
  関連の項目の読み込み、実地棚卸の送り方、分類の構造の MAS での名前。

## 6. 読み込みの道具（MxLoader）の標準の雛形（参考）

Maximo に同梱の構造で作られている雛形: 人員、労務、分類、資産、運用場所、品目、工具、倉庫、在庫、在庫の残高、作業指示、利用者。
専用の構造を作る必要がある雛形: 人員グループ、故障コード、故障の一覧、資産の予備品、作業計画、ルート、会社、単位、コモディティ、通貨。
