# MX Stage の Skill の仕様

2026-10-03 に案を作り、2026-10-05 に利用者の了承を得て実装した（目次 1・基本動作 8・標準オブジェクト 8）。
標準オブジェクトの割り出しは `docs/maximo-load-patterns.md`。

## 1. 方針

- **メインの Skill は目次**にする。全作業に共通の決まりと、ほかの Skill の一覧（どの場面で読むか）だけを持つ。
- **既定の Skill（製品に同梱）は 2 層**にする。
  - **基本動作**: 読み込み・分析・変更・突き合わせ・取り込み・反映・画面の振る舞いなど、どのオブジェクトでも同じ動き。
  - **標準オブジェクト**: 資産・場所・作業指示・発注など、Maximo の標準のオブジェクトごとの振る舞い。
    Maximo の標準機能の中で考えられる読み込みと投入のパターンをすべて割り出し、よく行うものを厳選する（5 章）。
- **客先のカスタムのオブジェクト・属性・表に合わせた Skill は、利用者が客先の環境ごとに作る**（利用者の Skill）。
  その作り方も既定の Skill として同梱する。
- 安全の決まり（API キーを受け取らない、推測で埋めない、反映は利用者が押す、範囲を合意してから読む）は、
  どの Skill からも上書きできない。目次にだけ書き、ほかの Skill は重ねて書かない。

## 2. 層と名前

| 層 | 名前 | 中身 | 置き場所 |
|---|---|---|---|
| 0. 目次 | `mxstage-workbench` | 共通の決まり、最初の確認（get_status）、既定と利用者の Skill の目次と読む場面、利用者の Skill の参照の仕方 | リポジトリの `skills/` |
| 1. 基本動作 | `mxstage-core-<動作>` | 下の表 | 同上 |
| 2. 標準オブジェクト | `mxstage-obj-<オブジェクト>` | 5 章で決める | 同上 |
| 3. 利用者 | 自由（例 `<客先>-<作業>`） | 客先のカスタム、客先の決まり、繰り返す作業の手順 | `~/.config/mxstage/skills/` |

基本動作の候補:

| 名前 | 中身 |
|---|---|
| `mxstage-core-load` | 構造を探す、属性を読む、範囲の合意（scope_options）、読み込み（load_sheet）、参照先のマスタ（load_master）、子の条件・maxRows |
| `mxstage-core-analyze` | 集計と行の読み方（aggregate・query_rows）、データの質の見方（欠け・重複・単位・型の違い） |
| `mxstage-core-change` | 条件で一括（apply_rule と dryRun）、行ごと（patch_cells）、行の追加と削除、取り消し |
| `mxstage-core-match` | 突き合わせ（lookup・match_sheets・複合キー）、一致しない・曖昧なものの扱い |
| `mxstage-core-import` | Excel・CSV の受け取り、見出しの行、列の対応、Maximo のシートとの突き合わせ |
| `mxstage-core-commit` | 差分の確認、反映の依頼、競合とエラー、結果の報告、本番のライセンス |
| `mxstage-core-screen` | 作業画面の振る舞い（関連する表を並べる・連動・横持ち・欠けの色・絞り込み・窓の移動・再読み込み）。利用者への案内に使う |
| `mxstage-core-skills` | 利用者の Skill の作り方（いつ提案するか、書き方、名前、客先ごとに分けること、save_skill） |

### 置き場所（層ごとに固定）

- **出どころは MX Stage の 2 か所だけ**: 既定（層 0〜2）は MX Stage に同梱（リポジトリの `skills/` から作る）、
  利用者（層 3）は `~/.config/mxstage/skills/<名前>/SKILL.md`。目次の添付・get_skill・list_skills はすべてここから返す。
- **`mxstage` で始まる名前は既定専用**。利用者の Skill の保存（save_skill）と読み込みで断る（今は同じ名前なら既定を優先して利用者の方を読まない）。
- フォルダは名前ごとに平らに並べる（`skills/<名前>/`）。層は `metadata.category` で持つ（クライアントの Skill のフォルダは入れ子を想定していない）。
- 目次の名前は、案の `mxstage` ではなく今までの `mxstage-workbench` のままにした（Claude の plugin の `mxstage` Skill と名前が重なるのを避け、
  導入済みの写し・plugin の案内・get_skill の呼び方を変えずに済ませるため）。
- クライアントの Skill のフォルダ（`~/.claude/skills` など）へは、今までどおり導入が中身ごと写す（写しが古くなれば get_status が知らせる）。
  案の「名前と説明だけの薄い写し」は、写しが古くなる問題が実際に出たら行う。

## 3. 形式

- 1 つの Skill は `<名前>/SKILL.md`。本文は 8,000 バイト未満、説明は 200 字以内（今の検証の規則のまま）。
- LLM が読むので本文は英語（利用者の言葉で答えることは目次に書く）。
- frontmatter の `metadata` に `category`（`index` / `core` / `object` / `user`）を持つ。既定の Skill は必須（目次は `mxstage-workbench` だけ）、利用者の Skill は省くか `user`。
- 層の中の並びは作業の順（`scripts/build-skills.ts` の `WORK_ORDER`）。
- 目次に載せる一覧は、各 Skill の `name`・`description`・`category` から作る（手で二重に書かない）。

## 4. 届け方

| クライアント | 目次 | ほかの Skill |
|---|---|---|
| Skill の仕組みが無い（Claude Desktop のチャット・Gemini など） | 会話で最初のツール呼び出しの結果に、目次の本文と全 Skill の一覧（層ごと）を添える | AI が get_skill で読む |
| Skill の仕組みがある（Claude Code・Codex・IBM Bob・Antigravity） | 導入で Skill のフォルダに写す。最初の結果にも添える | 同じく写す。get_skill でも読める |

- **読み落としの手当て**: 作業の入口のツールの結果で、読むべき Skill の名前を示す（`src/bridge/skillHints.ts`。会話の中で読んだ・知らせた Skill は繰り返さない）
  （例: MXAPIASSET を読み込んだら `mxstage-obj-asset`、仕様の子があれば `mxstage-obj-classification`、取り込みを受けたら `mxstage-core-import`）。
- 利用者の Skill が既定の Skill と同じ場面を扱うときは、利用者の Skill を先に読み、既定の Skill の手順を客先の決まりで置き換えてよい。
  ただし目次の安全の決まりは置き換えられない。

## 5. 標準オブジェクトの Skill の選び方

1. **割り出す**: Maximo の標準機能から、オブジェクト × 操作の表を作る。
   - オブジェクト: 資産、場所（運用場所・システム）、分類と仕様、メーター、作業指示（計画・実績を含む）、サービス要求、
     予防保全と作業計画・ルート、品目・在庫・倉庫、発注・購買依頼・受入、人員・労務・職種、会社、障害コード、ドメイン など。
   - 操作: 読む、属性を直す、子を足す・直す・消す、親を新しく作る、状態を変える（Maximo では状態の変更は属性の書き換えではなく専用の処理）、
     改訂（作業計画・発注など）、数量の調整（在庫）など。
   - 各セルに、Maximo の標準の手段（MXLoader・アプリ・REST）と、よく行う度合いと、MX Stage が今できるかを書く。
2. **厳選する**: よく行うもの、誤りが起きやすいもの、MX Stage の価値が出るもの（差分の確認・一括の修正・欠けの補完）を選ぶ。
3. **足りない機能を分ける**: 今の MX Stage にできない操作は、Skill に書かずに製品の課題として並べる。
   分かっているもの: 親のレコードの新規作成、状態の変更の処理、改訂、在庫の数量の調整など専用の処理。
4. **確かめる**: 仮想 Maximo で、Skill の手順どおりに読み込みから反映まで通す。
   仮想 Maximo にある構造: 組織、運用場所、資産、分類、資産属性、単位、障害コード、作業計画、予防保全、作業指示、サービス要求、
   メーター、メーターの読み値、品目、在庫、人員、労務、職種、人員グループ、会社、ドメイン。発注は無いので、選ぶなら足す。
5. **本物の Maximo で確かめるもの**を分けて残す（Maximo の業務ロジックが動く処理など）。

## 6. 残り

- 状態の変更・新規作成・関連の項目の読み込みは製品の課題（`docs/maximo-load-patterns.md` の 3 章）。できるようになったら標準オブジェクトの Skill に足す。
- 本物の Maximo で確かめること（同じく 5 章）。作業指示の STATUS の書き換えは、確かめるまで Skill で「テスト環境で 1〜2 件から」としている。
